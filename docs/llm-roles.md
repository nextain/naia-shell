# LLM 역할 분담 표준 (작은 모델 ↔ 큰 모델)

> 프로젝트의 스크립트·동기화·검증 작업에 어떤 모델을 쓰고, 무엇을 시키고 안 시키는지의 표준.
> 동기: 작은 모델에 판단·수정을 맡기면 **맥락 소실**로 정합성이 깨진다 (큰 위험). 역할을 명확히 가른다.

## 역할 분담 (불변 원칙) — 3 레벨

> **naia-agent 의 원조 2계층(`naia-settings/llm.json` main/sub)을 하네스 표준으로 정규화.**
> "머리쓰기·설계·실질 검증 = 상위(플래그십) / 형식 검증 = 하위(라이트) / 구조는 코드(LLM 무)."

| 레벨 | 하는 일 | 모델 | naia-agent 역할 |
|------|---------|------|------------------|
| **0. 결정론 (LLM 무)** | 구조·스키마·기계검증 합격기준 (F12/F13, doc-graph, mirror 해시, `brightness==popcount`) | 없음 (스크립트) | — |
| **1. 라이트 (하위)** | **형식 검증** + 번역(.agents→.users 미러) + 생성(초안) + **문제점 지적**(검출·리포트) + 자동동기화 | haiku / gemini-flash-lite / glm-flash | `sub` (형식·보조) |
| **2-a. 플래그십 — main (상위)** | **머리쓰기·설계·판단·수정** (대화하는 주 모델) | Opus / GPT-5.x / GLM-5.x | `main` (대화 Agent) |
| **2-b. 플래그십 — 리뷰어 그룹 (상위)** | **실질 적대 검증** (placeholder인가·미묘한 버그·설계 타당성) — main 과 *독립*(안티앵커링) | **claude · codex · glm-5.1** (다중 독립) | `sub` 의 reviewer 변형, but 플래그십 tier |

**핵심**:
- **형식 검증(레벨 0·1)과 실질 검증(레벨 2-b)을 가른다.** 기계로 판정 가능한 건 결정론/라이트로 싸게, 판단이 필요한 건 플래그십 적대 리뷰로. (→ `acceptance-criteria.md` 두 층.)
- **리뷰어 = 플래그십, 독립 다중.** 검증은 고위험이라 강한 모델. main 과 분리해 앵커링 차단(`review-pass` §9, `acceptance-criteria.md` §2.1). 구현 = **`review-pass` 스킬(adk 레벨)**.
- **라이트는 "지적"까지, 수정은 플래그십 + cross-check.** 작은 모델에 수정 위임 = 맥락 소실로 정합성 붕괴(큰 위험).
- **크로스리뷰 로스터(2026-05-30)**: claude · codex · **glm-5.1**(opencode `openrouter/z-ai/glm-5.1`). gemini-CLI 제외(응답 5분+ 불안정 — 검증층은 timeout+graceful degradation 필요, `review-pass` §6.3/§7). Vertex 등 유료 API 는 속도·신뢰 필요 시 옵션.

### Config SoT — `naia-settings/review.json`

리뷰어 그룹 + tier 정책의 **정본 config** = `naia-adk/naia-settings/review.json` (cross-repo SoT, `llm.json`(main/sub/embedded)의 형제). `tier_policy` + `reviewers[]`(플래그십 앱) + `stages`. `review-pass` 스킬과 naia-agent 가 소비. naia-settings 가 naia-agent·naia-os 설정 파일을 담는 구조 정합 — 프로젝트는 project-local `review-pass.yaml` 대신 이 정본을 가리킨다(또는 override). secret 은 `apiKeyRef`(이름)만.

| **나중 — naia-agent** | **다중 CLI + 다중 API key** | naia-agent 가 main/sub 라우팅 (이 어댑터를 라우터로 교체) |

### 단일 CLI 호출 방식 (검증됨 2026-05-30)

| CLI | headless | 라이트 모델 지정 | 동기화 스크립트 env |
|-----|----------|------------------|---------------------|
| **claude** | `claude -p` (prompt via stdin) | `--model haiku` | `MIRROR_LLM_CLI=claude MIRROR_SUB_MODEL=haiku` |
| **gemini** | `gemini -p "<prompt>"` | `-m gemini-3.1-flash-lite` (작은 모델 — flash 아닌 flash-lite) | `MIRROR_LLM_CLI=gemini` |
| **codex** | `codex exec "<prompt>"` | `-c model=<계정 가능 모델>` | `MIRROR_LLM_CLI=codex` (ChatGPT 계정 모델 제약 주의) |

> 기본값: claude 코드 환경이면 `claude -p --model haiku`. `scripts/mirror-translate.mjs` 가 위 env 로 분기.

## 디텍트 계층 (명백한 오류는 LLM 없이 즉시 잡힘)

오류 규모에 따라 **싼 것부터** 잡는다. 큰/명백한 오류는 결정론 스크립트가 즉시 디텍트하므로 모델이 불필요.

| 계층 | 무엇을 잡나 | 수단 | 비용 |
|------|------------|------|------|
| **1. 결정론 검사** (LLM 무) | **구조 틀림**(F12/F13 위반·미등록 dir), 미러 stale(해시 불일치), doc 고립, CI 증거/SDLC 위반 | `enforce-root-structure.sh`, `mirror-translate --check`, `check-doc-graph.mjs`, `ci-verify-*.mjs`, `src/test/*.test.mjs` | 0 (즉시) |
| **2. 작은 모델** | 1계층이 못 잡는 미묘한 것 — 용어 위반, 어색한 번역, 의미 불일치 **지적** | check-terminology + 작은 모델 | 낮음 |
| **3. 큰 모델 + cross-check** | 1·2 가 지적한 것 **수정·판단** | 메인 모델 (적대 검토 동반) | 높음 (필요할 때만) |

> 원리: **어느 정도 큰 오류는 1계층(결정론)에서 디텍트**된다 — 구조가 틀리면 즉시 안다.
> 모델(특히 큰 모델)은 결정론으로 못 잡는 미묘한 영역에만 투입. 싼 검사를 먼저, 비싼 판단을 마지막에.

## FE-SM-01 — 셸의 메인 모델과 작은 모델 (0.2.5 계획)

이 절은 위 개발 작업의 3레벨 원칙을 사용자 설정에 연결한다. 결정론 검사는 모델 없이 수행한다. 대화와 판단은 메인 모델을 쓰고, 기억 역할이 비어 있어도 작은 모델이 지정돼 있으면 기억 사실 추출과 압축 요약에 작은 모델을 쓴다. 두 역할이 모두 비면 기존 모델 없는 대체 경로를 쓴다. 실질 검토에 필요한 상위 모델의 독립성은 그대로 유지한다. 보조 Pi 에이전트와 대화 본문은 메인 모델을 쓴다. 이 절은 목표 명세이며 구현 완료 증거는 [요구별 시험 계획](requirements.md#요구별-시험-계획--메인-모델과-작은-모델)에 둔다.

### FE-SM-02 — 두 칸과 저장

설정 화면에 ‘메인 모델’과 ‘작은 모델’을 넓은 화면에서는 나란히, 폰 폭에서는 위아래로 둔다. 두 칸 모두 추천·가격·성능 순서로 고르는 모델 선택기를 제공한다. 구현 2회차 수정 전 첫 설정은 메인 `deepseek-v4-flash`와 작은 `gemini-3.1-flash-lite`를 채웠다. 메인 목표는 제공 목록에 Terra 6.1이 있으면 `xhigh`, 없으면 다음으로 이용 가능한 추천 서버 모델이다. 조사된 목록에서는 다음이 `solar-pro4`다. 두 모델의 목표를 위해 첫 설정·기본값 적용 경로를 함께 바꾼다([현재 동작과 목표](requirements.md#현재-동작과-이번-판-목표)). 작은 기본 후보는 카탈로그에 실제로 있는 Luna 식별자에서 고른다. 확인된 목록의 목표는 `gpt-5.6-luna`와 낮은 생각 수준(`low`)이다. 목록에 Luna가 없거나 목록을 얻지 못하면 유효한 옛 기억 설정을 먼저 이어받고, 그것도 없으면 ‘메인 모델 상속’을 보여 준다. 이미 사용자가 고른 값은 자동 기본값으로 덮어쓰지 않는다. `nano`는 추천과 작은 모델 목록에서 빼되 기존 명시 선택은 보존한다. `solar-mini`는 추천 기본값이 아닌 국내 모델 선택지로 둔다.

정본 열쇠는 `llmRoles.main`과 `llmRoles.sub`다. 별도 `small` 역할은 만들지 않는다. 이전 `provider`·`model`, `subLlmProvider`·`subLlmModel`·`subLlmBaseUrl`·`subLlmCredentialRef`도 읽고 쓰며 기존 선택을 이어받는다. `llmRoles.memory`와 `memoryLlm*`는 독립된 기억 설정으로 보존한다. 옛 설정에서 작은 역할과 `subLlm*`가 비고 `memoryLlm*`만 있으면 작은 역할도 그 공급자·모델·주소·자격 참조를 이어받는다. 사용자가 작은 모델을 따로 정하면 작은 역할은 새 선택을 쓰고 기억 역할은 기존 기억 설정을 쓴다. 이는 옛 값의 읽기 호환이며 두 역할의 저장·수정을 합치지 않는다. 데스크톱은 선택한 작업 공간의 `naia-settings/config.json`, 웹은 브라우저의 출처별 전용 파일 시스템(OPFS)에 있는 같은 상대 경로가 정본이다. 화면용 임시 저장소는 정본 복원을 대신하지 않는다. 자격 증명 값은 설정 파일과 기록에 넣지 않는다.

목록의 Luna 기본값은 `subLlm*`·`llmRoles.sub`·`memoryLlm*`가 모두 비었을 때만 채운다. 첫 설정·작업 공간 로그인·설정 로그인·기본값 적용과 기존 작업 공간을 가져온 뒤 목록이 도착하는 경로에도 같은 조건을 적용한다. 유효한 옛 기억 모델만 있으면 목록 응답과 저장 뒤에도 작은 역할은 옛 기억 모델을 이어받고 기억 설정은 보존한다. 저장된 기억 끄기도 보존하며 모델로 해석하지 않는다. 구현 2회차 수정 전 목록 적용과 공통 슬롯 기본값은 옛 기억 필드를 확인하지 않았다. 셸 경로는 수정했으며 경로별 검증 범위는 시험 계획에 기록한다. 경로별 시험과 코드 근거는 [요구별 시험 계획](requirements.md#요구별-시험-계획--메인-모델과-작은-모델)에 둔다.

셸은 기본값 선택과 TypeScript 요청에 이어 데스크톱 Rust gRPC에서도 `xhigh`를 proto `XHIGH=4`로 전달한다. `off`·`low`·`high`는 각각 `OFF=1`·`LOW=2`·`HIGH=3`이고, 수준 부재와 알 수 없는 값은 `UNSPECIFIED=0`이다. legacy `enableThinking`의 true·false·부재는 독립적으로 보존한다. 셸 핀이 정한 에이전트·기억 커밋과 정규화 proto SHA가 모두 맞는 페어를 사용한다. 변환과 불일치 거절의 검증 범위·상태는 [시험 계획](requirements.md#요구별-시험-계획--메인-모델과-작은-모델)을 따른다.

### FE-SM-03 — 상속·실패·기록

명시된 기억 모델을 먼저 사용한다. 기억 모델이 비면 지정된 `sub`를 따른다. 기억이 비고 `sub`에 `inherit: "main"`이 명시되면 메인을 따른다. 작은 모델 목록 부재·조회 실패에 따른 새 설정도 이 상속을 명시한다. 옛 `memoryLlm*`만 있는 경우 기억과 범용 작은 모델 작업 모두 그 값을 이어받는다. **기억과 작은 모델이 모두 미설정인 기존 경로는 예외**다. 메인 설정이 있더라도 메인으로 보내지 않고, 사실 추출은 휴리스틱(정해진 규칙에 따른 추출), 압축은 기존 결정론 요약을 쓴다. 기억 끄기 선택도 보존한다. 그 밖에 작은 모델이 불완전하거나 지원되지 않으면 메인 상속을 적용하며 로컬 선택의 클라우드 차단을 지킨다.

작은 모델 호출이 실패하면 메인으로 같은 작업을 한 번만 재시도하고, 둘 다 실패하면 처음 오류를 보존한다. 각 실제 전송 전에 해당 대상의 승인을 확인하며 승인이 거부되면 전송하지 않는다. 작은 모델로 로컬 Qwen 4B를 직접 고른 경우 클라우드 메인으로 넘기지 않고 기존 휴리스틱 사실 추출 또는 결정론 요약으로 복구한다. 데스크톱에서만 로컬 선택지를 제공하고 8GB 이상 PC 안내를 보인다. 웹에서는 새 로컬 선택지를 보이지 않으며, 다른 환경에서 이미 고른 로컬 설정은 보존한다.

첫 실행과 로그아웃 뒤에도 로컬 모델은 사용자가 직접 고를 때 쓴다. 옛 자동 선택 요구와 로컬 받기 조건은 [다른 기존 요구와의 관계](requirements.md#다른-기존-요구와의-관계)를 따른다.

시도한 역할, 실제 공급자·모델, 성공 또는 실패와 대체 사유를 비밀과 대화 본문 없이 기록한다. `SmallLlmSection`의 기억 떠오름 선택과 꺼짐·점수 문턱 동작을 유지하며, 그 설정과 사실 추출용 역할의 우선순위는 [요구사항의 기존 설정 정리](requirements.md#기존-기억-설정과의-관계)에 따른다. 실제 웹 기억 소비 경로는 별도 과제로 다룬다.
