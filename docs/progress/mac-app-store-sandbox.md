# Naia 0.2.5 Mac App Store 샌드박스 계획

## 배경과 목표

대표님 원문(11/1, 0.2.5 쓰레드): “샌드박스용은 어떻게 해 ?”, “오늘 하는데 왜 제출 목표가 11/3이야 ?” 오늘 심사 제출을 위한 서명된 패키지와 실제 샌드박스 실행 증거가 필요하다. 앱 등록과 심사 제출은 조정자가 담당한다.

## 사용자 시나리오

사용자가 Mac App Store에서 Naia를 받아 설치하고 처음 실행한다. 로그인한 뒤 텍스트 대화와 음성을 사용하고, 작업할 폴더를 직접 선택한다. 샌드박스에서 지원하지 않는 기능은 이유를 알 수 있어야 한다. 직접 배포판은 기존 동작을 유지한다.

## 배포판 차이와 요구 사항

- 앱스토어판은 App Sandbox와 배포 프로필을 적용하고 앱스토어가 업데이트한다.
- 앱스토어판은 실행 코드·런타임 다운로드와 디지털 상품 외부 결제 경로를 제공하지 않는다. 모델 가중치 등 데이터와 실행 코드를 구별한다.
- 사용자 선택 폴더, 네트워크, 마이크에 필요한 최소 권한만 요청한다. 폴더 접근의 재시작 후 지속성은 별도 확인한다.
- Apple Silicon 앱의 모든 실행 코드를 적절한 상속 권한으로 서명하고, 앱과 설치 패키지를 각각 앱스토어용 인증서로 서명한다. 빌드 번호는 실행마다 증가한다.
- CI에서 패키지를 보관하고 Apple 검증 결과 및 별도 Developer ID 샌드박스 실행 증거를 수집한다. 앱 기록 준비 전 검증 실패는 제출 가능 판정으로 간주하지 않는다.

## 시험 항목

- 직접 배포와 앱스토어 빌드의 기능 제한을 단위 시험하고 기존 직접 배포 회귀를 확인한다.
- 기본·빈 목록·진행·성공·오류·좁은 폭 화면, 안내 문구, 키보드와 접근성을 실제 UI에서 확인한다.
- 코드 서명과 권한, 설치 패키지, altool 검증 출력을 확인한다.
- 앱을 실제 샌드박스로 90초 실행하고 자식 프로세스, 컨테이너, 거부 로그와 화면을 수집한다. 로그인·대화·음성·폴더 선택은 별도로 실사용 검증한다.

## 막힌 기능과 위험

| 기능 | 계획된 처리 | 현재 증거 |
| --- | --- | --- |
| 자체 업데이트 | 앱스토어판에서 끔 | 미구현 |
| 실행 파일·런타임 다운로드 | 앱스토어판에서 끔 | 미구현, 경로 전수 확인 필요 |
| 크레딧 외부 결제 | 앱스토어판에서 숨김 | 미구현, 모든 진입점 확인 필요 |
| 로그인·대화·음성·폴더 | 샌드박스 실사용 검증 | 미실행 |

Apple 심사 적합성과 실제 기능 동작은 서명·실행·심사 결과가 나오기 전까지 확인되지 않았다.
