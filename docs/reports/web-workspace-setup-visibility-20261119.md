# 웹 작업 공간 준비 버튼 가림 — 2026-11-19

## 문제와 범위

새 브라우저에서 로컬 모델이 준비됐어도 작업 공간이 `needs-setup`이면 전송이 차단된다. 실제 GPU 시험에서 준비 버튼의 좌표를 강제로 클릭하면 겹친 다른 요소가 클릭됐고, 버튼 DOM 클릭으로는 작업 공간이 준비되고 대화가 시작됐다. 답변 품질과 대화창 크기는 이 변경 범위 밖이다.

## 수정안

준비·설치·오류 UI를 스크롤되는 메시지 영역에서 꺼내 고정된 제스처 줄에 표시한다. 작업 공간이 준비되면 제스처가 다시 나타난다. 입력란과 모델 상태는 유지하며, 작업 공간을 준비하기 전 전송 차단도 유지한다. 준비 설명을 좁은 화면에서도 표시하고, 오류 메시지가 길면 줄을 나누고 스크롤할 수 있게 한다.

## 검증 계획

- 1280×720, 800×450, 390×844, 844×390에서 모델 상태가 여러 줄로 커진 조건을 만들고, 스크롤 또는 DOM 강제 클릭 없이 버튼 중심의 실제 포인터 대상과 클릭 후 `ready`를 확인한다.
- 긴 오류와 2배 글자 크기에서 다시 시도, 실제 Tab 순서로 진입 후 Enter, 준비 후 새로고침할 때 대화 복구를 확인한다. 설치 중 진행 상태는 별도로 확인한다.
- 실제 GPU 대화의 내용 품질은 이 시험으로 판단하지 않는다.

아래 현황에 적은 검증 전에는 배포하지 않는다.

## 검증 현황

- TypeScript 구문 변환과 `git diff --check`는 통과했다. 이는 타입 검사나 실행 시험이 아니다.
- 브라우저 회귀시험은 `/data` 여유 공간이 heavy-run 기준 미만이어서 아직 실행하지 못했다.
- 실제 스크린리더, 데스크톱, 클라우드 경로는 검증하지 않았다. 개발 서버에는 이 수정안을 반영하지 않았다.
